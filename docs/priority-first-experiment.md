# 중요한 일을 먼저 시작하는 실험

작업 브랜치: `feat/priority-first-start`.
변경 전 배포 상태 보관: `backup/pre-priority-20261102`, 커밋 `adcb94c`.
기존 `work/routine-original` 브랜치의 참조는 변경하지 않았다. 미커밋이었던 기존 작업은 새 브랜치의 기준 커밋과 백업 브랜치에 먼저 보존했다.

## 경험

1. 오늘 또는 내일 중요한 공부를 1~3개 정한다. 각 과목에 바로 할 행동, 준비물, 이어갈 분량, 2분/5분 작은 시작을 둔다.
2. 홈은 지금 할 한 가지를 우선 표시한다. 설정한 첫 행동에서 버튼 하나로 집중 타이머로 이동한다.
3. 이미 있는 계획 보상 규칙으로 지급이 발생했다면 전용 보상 페이지를 보여준 뒤 타이머로 연결한다. 새 보상 종류나 금액을 추가하지 않았다.
4. 첫 공부의 실제 작은 시간과 업로드해서 확인한 새 필기 사진을 모두 충족하면 첫 공부 사용 조건이 열린다. 사진만 또는 계획만으로 열리지 않는다.
5. 작은 시작이 끝나도 같은 중요한 과목을 계속 추천한다. 전체 분량까지 끝났다고 처리하지 않는다.
6. 다음에 바로 할 행동을 적고 타이머를 멈추면, 다음 홈 진입에서 다음 준비 과목을 추천한다. 이전 과목도 직접 골라 다시 이어갈 수 있다.
7. 내일 계획 복사와 지난 계획 가져오기는 저장 전 편집할 수 있다. 다음 행동을 첫 행동으로 가져온다.
8. 기록 통계에는 실제 첫 공부의 작은 시작을 확인한 날만 센다. 전체 목표 완료 점수나 임의의 스트릭 기준을 추가하지 않았다.

## 보상과 잠금

- 첫 계획을 저장하기 전에는 새 정책을 켜지 않는다. 설정 화면에서 사용 여부를 선택해 저장한다.
- 내일만 준비했다면 오늘을 갑자기 잠그지 않는다. 활성화한 날짜의 새벽 4시부터 적용한다.
- 아침 루틴 전체/작은 목표 완료와 첫 공부 작은 시작은 별개 조건이다. 양쪽 모두 충족해야 사용 가능하다.
- 다른 공부·단어·운동은 언제든 할 수 있고 기존 보상도 계속 적립한다. 순서를 어겼다고 개별 보상을 지우지 않는다.
- 첫 공부 조건에는 별도의 시간이나 돈을 지급하지 않는다. 기존 계획/사진 5분, 단계 증가, 단어 누진 보상, 돈 지갑 규칙은 유지한다.
- 첫 공부의 2분/5분은 해당 과목을 이 계획에서 시작한 이후의 실제 초만 센다. 기존 공부 시간, 정지 시간, 다른 과목 사진으로 충족시키지 않는다.
- 필기 사진이 기존 단계 보상에 대해서는 대기 상태여도, 첫 공부의 최소 실제 시간과 사진 요건을 충족하면 첫 공부 조건은 완료할 수 있다. 단계 보상은 기존 단계 시간이 채워져야 지급한다.
- 기존 +60분 순서 보너스는 해당 설정의 전체 기준을 그대로 따른다. 작은 시작 설정이 그 기준을 덮어쓰지 않는다. 계획 화면에서 별도 순서를 확인할 수 있다.

## 구현

- `priorityPlan.ts`: 계획, 시작 기준점, 사진 증거, 완료·다음 행동·재개, 선택적 기존 데이터 호환 및 백업 검증.
- `PriorityPlanScreen`, `PriorityMissionCard`, `PriorityHistoryCard`: 준비, 홈의 행동, 중단·복귀, 기록.
- `RoutineProvider`: 영수증 정산 후 첫 공부 진행을 저장하고 네이티브 조건과 동기화.
- 네이티브 `setPriorityGate`: 공유 잠금 상태에 적용 시작일과 완료 여부를 저장한다. 앱을 닫아도 차단 조건을 유지하며 새벽 4시에 완료 여부를 초기화한다. 앱과 모니터 확장은 동일한 공유 코드를 사용한다.
- 이전 설치본은 `supportsPriorityGate`가 없어 새 기능이 실제 기기에 적용됐다고 표시하지 않는다. 화면에 새 빌드 필요를 안내한다.

**이 브랜치는 아직 배포하지 않았다.** 새 네이티브 메서드와 공유 잠금 상태가 추가됐으므로 기존 TestFlight 36번에 OTA만으로 완전 적용할 수 없다. 웹 확인 후 새 iOS 빌드가 필요하다.

## 검증

- 타입 검사, 전체 기존 테스트와 새 정책 테스트.
- 48개 테스트 묶음, 293개 검사 통과. 웹 흐름은 `node scripts/check-priority-first-web.cjs`로 재현한다(로컬 웹 서버 필요).
- 별도 브라우저 저장소에서 오늘/내일 계획, 준비한 행동에서 2분 시작, 기존 계획 보상만 지급, 실제 시간과 사진 확인, 첫 공부 조건 완료, 다음 행동 저장 후 복귀, 다음 과목 추천, 내일 복사, 360px 화면을 확인했다.
- 브라우저 테스트의 실제 공부 경과와 AI 인식 결과는 명시적인 검수 데이터로 넣었다. 유료 OCR을 호출하거나 실제 사용자의 기록을 덮어쓰지 않았다.
- 스크린타임 권한/공유 타깃/자동 연결 정적 검사와 공유 Swift 파일 동기화 검사 통과.
- Windows에서 Swift를 컴파일하거나 실제 아이폰 앱 차단을 실행해 확인한 것은 아니다. 새 빌드에서 권한 연결, 앱 종료 후 차단, 새벽 4시, 첫 공부 완료, 시간 사용 켜기, 잔액 보존을 확인해야 한다.

## 바로 확인

- 일반 웹: `http://localhost:8082/`에서 오늘 또는 설정 → 중요한 공부·첫 행동.
- 공부 예시: `http://localhost:8082/?priorityDemo=1`. RoutineProvider 저장소는 `routine.v1.web-priority-demo`로 일반 루틴 기록과 분리하며, 예시 초기화는 이 키만 지운다. 웹은 iOS 앱 차단을 실행하지 않는다.
- 공부 종료 준비는 공부 화면의 닫기 또는 `멈추고 메모`에서 전용 `PriorityPause` 화면으로 연결한다. 한 줄 저장과 메모 없이 정지 모두 가능하다.

## 돌아가기

현재 기능 커밋 후 작업 내용이 없는 상태에서 `git switch backup/pre-priority-20261102`로 실험 전 상태를 확인할 수 있다. 다시 `git switch feat/priority-first-start`로 돌아온다. 브라우저/앱의 저장 데이터는 브랜치 전환으로 되돌려지지 않는다.
