# 홈 → 시작 → 공부 → 제출 → 보상 UI 정리

브랜치 `feat/priority-first-start`. 로컬 Expo SDK 54 웹에서 구현·검수했으며 배포하지 않았다.

## 화면별 기준

| 화면 | 먼저 답할 질문 | 주요 행동 | 보조 정보 |
|---|---|---|---|
| 홈 | 지금 무엇부터 할까? | 준비한 행동에서 2분/5분 시작 | 다른 과목은 펼쳐 선택, 실제 잔액·시간 사용·루틴·일정은 아래 |
| 시작 | 어디서부터 시작할까? | 준비한 첫 행동에서 바로 시작 | 새 계획 보상이 생긴 경우 기존 보상 화면을 거침 |
| 공부 | 지금 계속 공부하고 있는가? | 진행 중에는 정지/재개, 시간 충족 시 사진 제출 | 휴식은 수동, 시간 조정은 펼쳐 사용, 과목명은 기본 숨김 |
| 제출 | 무엇을 제출하면 될까? | 사진 찍기 → AI로 읽기 → 인식 내용 확인·저장 | 보상 기준·이전 필기는 펼쳐 보기, 타이머 복귀와 다음 행동 저장 유지 |
| 보상 | 이번에 무엇을 쌓았고 다음은 무엇일까? | 공부 시작하기 / 이어서 공부하기 | 실제 지급·보류·사용 가능 잔액, 즉시 닫기 유지 |

Taste 앱 화면 지침과 ECC frontend-design-direction/coding-standards/verification-loop를 적용했다. Taste workspace 방향의 개인 중심·한 겹 정보 구조를 참고하고, 프로젝트 지침에 따라 데스크톱 그리드·서체·색상 규격은 강제하지 않았다. 기존 파랑, 동물 4종과 Lottie, 전체 화면 축하를 유지했다. 방향 기록은 `.expo/action-flow-after/direction.json`에 있다.

## 변경과 보존

- 첫 행동을 지표와 시간 사용 설정보다 먼저 표시한다. 다른 과목도 잠금 없이 선택할 수 있다.
- 타이머의 조정 버튼 4개는 펼침으로 이동하고 사진 제출 경로를 명시했다. 목표가 지나도 공부는 계속된다.
- 제출 화면의 중복 타이머·시작 설정·보상 설명 카드를 줄였다. 활성 집중이 없거나 계획 재시작이 필요하면 시작 폼을 유지한다. 휴식 중 새 집중 시작도 가능하다.
- 사진 선택 전에는 촬영, 선택 후에는 AI 읽기, 인식 후에는 저장이 주요 버튼이다. 개인정보 전송 안내와 오류, 재촬영, 이전 기록, 과목 종료는 보존했다.
- 보상 버튼이 재지급처럼 보이는 '보상받기' 대신 다음 행동을 표시한다. 적립은 기존 저장 함수에서만 일어난다. 필기 보상 뒤에는 진행 중인 타이머로 복귀한다.
- 작은 보상 화면에서도 캐릭터·실적·잔액·다음 버튼을 함께 볼 수 있도록 크기와 간격을 조정했다.
- 홈 지표의 10px 글씨를 12px로 키우고 캐릭터 장면 글씨 대비를 개선했다. 타이머 버튼은 최소 44px이다.
- 기존 미커밋 파일과 패치는 `.expo/action-flow-before/source/`, `existing-changes.patch`에 추가 보존했다. 캐릭터 확대, 실제 지표, 작은 시간 사용 토글 변경은 유지했다. 도메인 보상/잠금/저장/04시 경계와 네이티브 코드는 변경하지 않았다.

## 실제 확인 결과

검수용 브라우저 컨텍스트와 예시 저장소를 사용했다. 유료 OCR은 호출하지 않았다. 실제 공부 경과와 OCR 성공 응답은 명시적인 검수 데이터다.

- `npm.cmd run typecheck`: 통과.
- `npx.cmd expo export --platform web --output-dir .expo/action-flow-after/export --max-workers 2`: 로컬 웹 내보내기 통과. 배포 아님.
- `npm.cmd test -- --runInBand`: 48 suites / 293 tests 통과.
- `npm.cmd run check:screen-time`: 정적 검사 통과.
- `node scripts/check-priority-first-web.cjs`: 오늘/내일 계획, 작은 시작, 기존 계획 보상, 사진·시간 조건, 중단·다음 행동 저장·복귀 통과.
- `node scripts/check-priority-ui-layout.cjs`: 360×740 / 390×844에서 시작 버튼 전체 노출, 순서 변경·편집, 다크 테마 통과.
- `node scripts/check-action-flow-ui.cjs`: 홈→보상→타이머→사진→인식 확인→보상→타이머를 직접 이동. 가로 844×390 포함 주요 버튼 44px 이상·화면 안 노출, 가로 넘침 없음. 키보드 Enter 시작, 모션 줄이기, 사진 선택 중 버튼 비활성, 사진 미리보기, 미로그인 오류 후 재시도 가능, 시간 미충족 안내, 다크 제출 화면, 재진입 후 영수증 중복 없음 확인.
- Taste inspect: 360/390px **0 FAIL / 4 WARN**. 남은 경고는 예시 초기화 링크 대비, 아이콘/Lottie 색상을 차트로 인식한 색상 개수, 작은 보조 문구 비중, 기존 따뜻한 캐릭터 배경이다. 완전한 접근성 감사 통과를 의미하지 않는다.
- Taste source lint: 0 FAIL / 2 WARN. 시계의 `padStart`는 시간 표시 용도다. 별도 린트 명령은 package.json에 없다. ECC 화면 검증 evidence checker도 통과했다.

화면 캡처: 변경 전 `.expo/action-flow-before/`, 변경 후 `.expo/action-flow-after/`.
주요 버튼의 실제 좌표는 `measurements.json`에 있다. 예시 화면 홈 시작 버튼은 390×844에서 y=485, 360×740에서 y=429이며 높이는 모두 58px이다. 인식 확인·저장 버튼은 두 화면 모두 y=643, 높이 58px으로 화면 안에 표시된다.

Windows 웹 검수다. 실제 iPhone의 카메라 권한·가로 회전·Screen Time 차단·Lottie 성능, 로그인 후 실제 OCR, 서버 장애는 미검증이다. 빌드·배포·원격 데이터 변경은 하지 않았다.
