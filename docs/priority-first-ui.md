# 중요한 공부 실험 UI 두 번째 수정

브랜치: `feat/priority-first-start`. 제품 정책과 기록 구조는 유지하고 화면 구성과 조작 흐름을 수정했다. 아직 배포하지 않았다.

- 홈: 시간 사용을 한 줄 영역으로 합치고 첫 행동·캐릭터 장면·시작 버튼을 우선 표시. 준비물과 이어갈 분량은 펼쳐서 확인한다. 루틴과 학습은 네 개의 바로가기와 자유 공부 링크로 접근한다. 일정·기록·순서 보너스·돈 지갑 진입은 유지했다.
- 계획: 한 공부만 펼쳐 편집. 필요한 입력은 과목과 첫 행동, 나머지는 선택 항목으로 접었다. 순서 이동과 삭제는 항목 메뉴에 모았다. 저장 후 홈으로 바로 복귀한다.
- 멈추기: 다음 첫 행동 한 줄에 집중. 저장·중단과 메모 없이 중단을 구분한다.
- 공통: 선명한 파랑과 따뜻한 캐릭터 장면, 간결한 하단 탭, 작은 화면 대응, 명확한 입력 포커스, 누름 반응. 저장/중단/시작 버튼의 아이콘을 구분했다.
- 스크롤: 계획을 수정한 뒤 돌아오면 새 첫 행동을 보여준다. 홈을 읽는 도중 데이터가 갱신됐다는 이유만으로 스크롤을 움직이지 않는다.
- iOS 편집과 멈추기 화면에 키보드 회피 레이아웃을 적용했다. 실제 아이폰 키보드는 별도 검수가 필요하다.

소스: DashboardScreen → PriorityHomeScreen, PriorityPlanScreen → PriorityPlanEditor, PriorityMissionCard → PriorityMissionView, PriorityPauseScreen → PriorityPauseView, MainTabs → PriorityTabs.

검증: 타입 검사와 전체 293개 테스트, 오늘/내일 계획부터 공부·사진·보상·복귀까지의 웹 흐름 통과. 별도 레이아웃 검수에서 390×844와 360×740의 시작 버튼이 탭 위에 완전히 표시됨, 가로 넘침 없음, 한 항목 편집, 선택 필드 접힘, 순서 메뉴 이동, 어두운 테마, 브라우저 오류 없음 확인. `node scripts/check-priority-ui-layout.cjs`로 레이아웃 검수를 다시 실행할 수 있다.

확인 주소: `http://localhost:8082/?priorityDemo=1`. 예시 루틴 저장소는 일반 루틴 기록과 분리된다.
