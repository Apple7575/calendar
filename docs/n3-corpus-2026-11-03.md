2026-11-03. 브랜치 `feat/n3-concept-flashcards`. 이전의 [111문항 1차 확장](n3-grammar-reading-listening-2026-11-03.md)에 이어, 어휘를 제외한 **PDF 166–374쪽, 총 209페이지 전부**의 추출·첫 검수를 실행했다. 작업을 설명만 하고 멈춘 상태가 아니다. 종료 시 실행 중·대기 배치는 0개다.

**완료:** 전체 범위의 페이지 검토, 원문 추출, 별도 이미지 검수, 로컬 OCR 대조, 통과 자료의 앱 반영, 합성 청해 제작·재전사·재생 확인. **미완료:** 확인 필요 214문항의 문제 해결, 사람의 전수 언어 검수, iPhone 실기기 검증. 모든 원문이 오류 없이 완성됐다고 표시하지 않는다.

이번 교재 추출 카드는 776개다. 기존 실험 자료를 합치면 전체 카탈로그 **903개 중 학습 가능 686개, 보류 217개**다. 기존 실험 어휘 표본 5개는 기본 새 학습에서 제외하며, 기존 단어장을 계속 사용한다. 교재 추출 중 기존 N3의 단어 뜻 카드·이미 있는 개념 뜻 카드·전략 설명을 그대로 외우는 카드 등의 중복/부적합 항목은 별도 제외 기록에 남겼다. 기존 N3/N2에 새 내용을 합치지 않았다.

원문 추출 레코드와 카드 수는 집계 단위가 다르다. 한 독해·청해 레코드는 여러 질문 카드로 펼쳐지며, 같은 개념의 중복 뜻 카드는 통합한다. 원문 레코드 수를 곧 학습 문항 수로 세지 않는다.

보류 이유는 원문/OCR 불일치, 판독·문맥·지문 누락, 정답·접속 조건 불확실, 그림 의존, 검수 미승인 등이다. 문항 번호만 있고 실제 대본·질문이 인쇄되지 않은 청해 페이지는 원문 내용을 지어내지 않았다. 이런 원자료의 빈칸까지 해결됐다는 뜻은 아니다. 별도 AI 연습 자료와 합성 음성으로 각 청해 유형을 연습할 수 있다.

## 추출·검수 방법과 한계

1. 단원 경계를 지키는 55개 묶음으로 전 209페이지를 처리했다. 각 묶음의 앞뒤 페이지는 이어지는 지문 확인용이며, 시작 페이지가 핵심 범위 밖인 문항은 중복 추출하지 않는다.
2. 이미지 기반 원문 추출과 별도 이미지 검수 호출을 분리했다. 승인/보류가 상충한 항목은 보류 판정을 우선한다. 모델이 보고한 항목 수 대신 실제 승인·보류 ID 집합을 검사한다. 응답이 잘린 검수는 원본 결과를 재사용해 필요한 검수만 명시적으로 보완했다.
3. 문법은 개념·접속과 원문 문제, 글의 문법·독해는 전체 지문과 질문 묶음, 청해는 실제 인쇄된 대본과 질문을 구분했다. 단원 학습 전략을 무조건 개념 카드로 바꾸지 않았다.
4. 149페이지의 유형을 추가 분류했다. 이미지 모델이 한국어 해석 페이지를 일본어 원문으로 잘못 인식하는 사례도 발견해, 이미지 승인만으로 게시하지 않았다.
5. 전 209페이지에 Windows 일본어·한국어 OCR을 모두 수행하고 좌표 원문을 저장했다. 일본어 근거 문장과 로컬 OCR의 겹침을 별도로 비교해, 한국어 해석에서 재구성한 일본어나 원문과 안 맞는 항목을 보류했다. 이 자동 대조도 완벽한 정확도 보장은 아니며, OCR 오독 때문에 정상 항목이 보류될 수 있다.
6. 직접 원본을 확대 대조한 4건의 수정은 별도 `visual-corrections.json`에 이미지 해시와 기록했다. 이는 작업 모델의 시각 대조이며 사람의 검수라고 쓰지 않았다.
7. 앱의 필수 필드·근거·개념 연결·정답 노출·묶음 검증을 다시 통과한 카드만 학습에 내보낸다. 빈 질문이 있는 보류 자료 때문에 전체 저장이 실패하지 않도록 ‘원문 확인 필요’ 표식을 둔다. 이를 실제 질문/정답으로 채워 넣지 않는다.

원문/추출 결과는 상위 `output/concept-lab/n3-20261102/corpus/`의 `*-draft.json`, `*-review.json`, `*-raw.json`, `jobs.json`, `progress.json`, `page-language.json`, `ocr-grounding.json`, `packaged-coverage.json`에 남아 있다. 원문·실패 결과를 지우거나 무한 재시도하지 않았다. 기존 `pages/*-ja.json`, `*-ko.json`은 원문 OCR 증거다.

## 앱에서 사용하는 방식

미리보기: **http://localhost:8082/?conceptDemo=1**. 이미 열어 둔 브라우저는 새로고침해서 최신 카탈로그를 불러온다.

- 문법 → 독해 중심의 하루 새 학습량 제한을 유지한다. 새 문항 수가 많아져도 하루에 전부 배치하지 않는다.
- 카드 목록은 **검색·영역 필터·40개씩 더 보기**를 제공한다. 표현뿐 아니라 `PDF 362`처럼 쪽수로도 찾는다. 오늘의 순위 밖 카드도 실제 남은 새 학습량·복습 일정·묶음 조건 안에서 직접 선택할 수 있다.
- 긴 지시문 대신 상황, 목표 표현, 시제·말투를 짧은 줄로 표시한다. 원문의 보기 정보가 질문 본문에 없으면 보기 전체를 별도로 표시한다. 필요한 정보를 줄여 버리거나 정답만 표시하지 않는다.
- 독해·청해는 모든 질문을 떠올린 뒤 해설을 공개한다. 독해 지문은 해설 화면에서도 다시 볼 수 있다. 청해 대본은 응답 전 숨긴다.
- 새 자료를 기존 실험 저장소에 추가할 때 응답·FSRS·사용자 수정·신고를 보존한다. 단원 간에 같은 문법 개념을 연결할 수 있지만 어휘 개념과 문법 문제를 섞지 않는다.
- 원문 카드의 검수 상태가 바뀌면 사용자가 수정하지 않은 자료만 보류/승격 상태를 갱신한다. 일정과 응답 이력은 재설정하지 않는다.

기본 단어 카드의 원문·읽기·음성 연결과 기존 루틴의 보상·잠금 규칙은 변경하지 않았다. AI 오답 변형은 여전히 **추천 → 직접 체크 → 생성 → 검토 → 추가**이며 자동으로 쌓지 않는다. 새 청해 변형을 온라인으로 생성하는 기능까지 연결한 것은 아니다.

## 합성 청해 8개

기존 AI 연습 음성 3개에 **교재 기반 5개**를 더했다. 새 5개는 과제 이해, 포인트 이해, 개요 이해, 발화 표현, 즉시 응답 각 1개다. 실제 인쇄된 대본·상황 예문을 사용하고 원음 녹음이라고 표시하지 않는다.

대화는 역할별 alloy/nova 음성으로 나눠 합성 후 결합했다. 질문의 빈 응답 부분은 읽지 않는다. 원문 대본과 정답을 드러낼 수 있는 단서는 청해 앞면에 표시하지 않는다. 새 파일은 `tts-1`로 제작하고 `whisper-1`로 재전사해 핵심 사실을 대조했다. 자동 전사는 일부 표기·고유명사를 다르게 인식할 수 있으며 사람의 청취 평가를 뜻하지 않는다.

음성·문제 지문·정답은 각각 구분해 저장했다. 음성 파일은 `assets/concept-lab/audio/`, 연결은 `corpusAudioAssets.ts`와 `corpusListening.json`에 있다. 반복 재생과 제작 스크립트 재실행은 저장된 파일을 재사용하며 새로운 합성 호출을 하지 않는다. 원문과 맞지 않는 대본은 음성 제작 대상에서 제외했다.
