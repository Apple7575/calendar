## 후속 조정: 여러 줄의 시작선과 빈칸 표시

문장형 카드의 단서 텍스트·문제·지시·여러 줄 정답을 카드 내부에서 왼쪽 정렬한다. 카드 바깥에 붙이지 않고 아이콘 열(22px)과 간격(8px)을 둬 본문의 시작선을 맞췄다. 어휘 한 단어의 큰 가운데 표시는 유지한다. 빈 괄호/밑줄은 원래 문장 위치에서 연필 아이콘·밑줄·테마 강조색으로 표시한다. 입력창은 만들지 않았고, 접근성 레이블은 ‘빈칸: 여기에 들어갈 표현을 떠올려 보세요’다.

TypeScript 및 4개 표본 앞뒤 브라우저 확인 통과. 360/390/768px에서 단서·문제·지시 텍스트의 실제 x좌표가 각각 동일함을 측정했고, 가로 넘침·정답 사전 노출·입력창이 없음을 확인했다. 근거 `.expo/concept-lab-20261102/alignment-qa.json`, `aligned-blank-*.png`. 배포하지 않았다.

## 후속 조정: 아이콘 단서와 ‘다시’ 즉시 이동

단일 카드의 ‘다시’도 다른 평가처럼 한 번 누르면 저장·다음 카드로 이동한다. 추가 확인 버튼을 제거했다. 단일 카드에서는 오답 원인 입력 때문에 진행을 멈추지 않으며, 기존 원인 기록은 보존한다. 지문 묶음은 각 질문의 평가를 모아서 저장하는 흐름을 유지한다.

짧은 문구는 ‘검은 구름 관찰’ 같은 불분명한 명사구 대신 **눈 아이콘 + 검은 구름이 보임**으로 표시한다. 전달 문제는 **말풍선 아이콘 + 예보에서 내일 비라고 함**이다. 실제 앱은 기존 Ionicons를 사용하며, 접근성 레이블에는 직접 본 정보/들은 정보를 명시한다. 정답은 뒤집기 전 숨기고 원문·긴 해설·진도는 유지한다.

TypeScript와 관련 22개 테스트 통과. Chrome에서 ‘다시’ 즉시 이동·Again 기록 저장·기존 일정 보존·아이콘 예시·긴 해설 펼치기를 검증했다. 이 변경도 미배포다. 아래 이전 기록의 추가 확인 버튼/단일 카드 원인 선택은 현재 흐름이 아니다.

## 후속 예시: 문제·해설을 핵심어로 줄이기

어휘 읽기·추측 빈칸·전달 상황·추측/전달 비교의 4개 표본에 짧은 표시 문구를 추가했다. 실험 홈의 **짧은 카드 예시 · 4장**에서 앞뒤를 넘길 수 있으며 이 미리보기는 평가·일정을 저장하지 않는다. 예: `검은 구름 관찰 / 雨が（　）。/ 降る → 추측·보통체`, 핵심 해설은 `관찰 → 추측 / 降ります → 降りそうだ`. 일본어 정답 문장은 자연스러운 문장으로 유지하고, 긴 원래 설명은 펼쳐보기로 남겼다.

표시 계층만 바꾸어 기존 질문·정답·근거·복습 이력을 유지한다. 같은 4개 표본은 일반 실험 학습에서도 짧게 보인다. 사용자가 직접 고친 카드 또는 원본과 다른 리비전에는 예시 문구를 강제로 덮어씌우지 않는다. 전체 교재·모든 문항의 문구를 바꾼 것은 아니다.

실제 데이터는 `conceptLabUnits.ts`와 생성한 서버 `catalog.json`이다. 모든 단원에 목표 능력, 추출 대상, 카드 유형, 채점 기준, 변형 시 유지/변경 요소, 태그, 근거 범위, 검토 상태가 있다. 범위는 PDF 목차와 파일 끝을 기준으로 하며 인쇄 쪽수를 미확인 페이지에 일괄 추정하지 않는다.

| 분류 | 세분 단원 | 처리 원칙 |
|---|---|---|
| 어휘 | 한자 읽기 / 표기 / 문맥 규정 / 유의 표현 / 용법 | 독음·표기·뜻·공기 표현을 분리. 같은 단어라도 한 번에 평가하는 능력은 하나 |
| 문법 | 빈출 개념 / 형식 판단 / 문장 만들기 / 글의 문법 | 의미·접속표·활용과 담화 연결을 구분. 표의 품사·긍정/부정을 보존 |
| 독해 | 단문 / 중문 / 장문 / 정보 검색 | 지문·질문을 묶음으로 저장. 개념 ID를 억지로 부여하지 않고 능력 태그로 관리 |
| 청해 | 과제 / 포인트 / 개요 / 발화 표현 / 즉시 응답 | 음성·대본·질문·해설을 분리. 원음 없는 문제는 보류 |

대표 표본은 休日·日時, 추측/전달의 そうだ, 수수 표현, 글의 연결, 지시어가 가리키는 상황, 청해의 최종 결정을 골랐다. 문장 배열 및 나머지 단원 전체 추출·문항 생성 품질은 아직 검증하지 않았다.

## 저장 모델과 학습 흐름

별도 키 **`routine.concept-lab.v1.<account>`**, 교재 ID **`n3-concept-lab`**, 카드 ID **`lab_…`**를 쓴다. 기존 `routine.v1.*`, N3/N2 카드·FSRS·계획·즐겨찾기·보상·원본 음성은 건드리지 않는다. 이 실험 저장소는 현재 기기/브라우저 로컬이며 기존 클라우드 백업·동기화에 포함하지 않는다.

- `Concept`: 어휘·문법 개념, 원문 근거와 태그. 여러 카드가 같은 개념에 연결된다.
- `LabCard`: 하나의 목표 능력, 유형, 질문, 예상·허용 답안, 해설·힌트·루브릭, 원문/AI, 기본/변형, 부모 ID, 품질·보류 상태.
- `ProblemBundle`: 지문 또는 청해와 질문 ID 목록. 독해·청해는 개념 없이 능력별로 관리할 수 있다.
- `schedules`: **카드별** 기존 FSRS 상태. 변형 카드 추가 시 원래 카드 일정을 복사하거나 초기화하지 않는다.
- `session.answers`: 먼저 제출한 응답·시간·힌트·응답 방식. 중단 후 이어 할 수 있다. 묶음은 모두 응답해야 정답·해설 공개.
- `attempts`: 확정 자기 평가, 실제 일정에 쓴 grade, AI 참고 평가, 첫 응답 여부, 원문/AI, 변형 여부, 능력, 오답 원인. 음성은 전사 텍스트와 방식으로 기록하며 녹음 파일은 별도 축적하지 않는다.
- `corrections`: 원래 평가를 삭제하지 않는 수정·이의 기록. 수정 시 해당 카드의 일정만 이력 순서대로 다시 계산한다.
- `reports` / `revisions`: 문제 신고로 비활성화, 수정 전 내용 보존. 활성 세션의 문제를 신고하면 중단하고 이미 제출한 답은 `archivedSessions`에 보존한다.

오늘 학습 → 문제/묶음 → 먼저 응답 저장 → 정답·짧은 해설 → 자기 평가·선택적 원인 → 일정 저장 순서다. 기본 문답·역방향·빈칸·형태 변환·비교·상황 적용·음성의 7유형을 렌더링한다. 선택지 응답과 직접 입력, 말하기 입력과 자기 회상을 구분한다.

허용 답안과의 일치는 표시하지만 목록 밖의 답을 자동 오답으로 단정하지 않는다. 작문·비교는 루브릭과 자기 평가를 사용하고, 서버 연결 후 AI 참고 채점을 요청할 수 있다. AI 평가가 낮은 확신이면 판단 보류로 표시한다. **실제 일정과 최종 판단은 별도 자기 평가**를 따른다. 오답이면 Again, 힌트를 쓴 정답은 최대 Hard로 제한한다.

원인은 기억 실패 / 개념 혼동 / 어휘·문장 이해 부족 / 문제 해석 실수 / 직접 입력이다. 반복 오답·기본 정답/변형 오답·의미 정답/활용 오답·문자 정답/듣기 오답·선택지 정답/직접 응답 오답을 근거로 연습을 추천한다. 속도만으로 암기 여부를 판정하지 않는다. 현재 적응 방식은 **유한한 검수 변형 풀의 우선순위 추천 + 사용자의 수동 추가**이며, 무제한 온라인 자동 생성이 아니다.

일일 새 학습은 기본 6개(0–30), 새 적용 문제 추가는 기본 2개(0–5), 같은 개념의 추가 간격은 1/3/7일이다. 검수된 기존 복습을 먼저 배치하고 묶음 전체가 한도에 들어갈 때만 새 묶음을 시작한다. `새 적용 문제 첫 응답`은 첫 노출만 집계하고 변형 재복습은 따로 표시한다. 여러 날 새 문제를 맞힌 기록을 보존하되 능력 전체를 초기화하거나 개념 전체 간격을 임의 배수로 늘리지 않는다. 간격 증가는 실제 카드별 FSRS 응답에 따른다.

## AI 서버: 작성됨, 아직 원격 미연결

`supabase/functions/concept-lab/`에 생성·검증·채점 서버를 작성했다. 앱은 기본적으로 온라인 미연결 상태를 표시하고, 로컬 검수 표본과 자기 평가로 실행된다.

온라인 경로는 다음을 구현했다:

1. 로그인 JWT를 `getUser`로 확인하고 익명 계정은 제외. 서버 허용 계정 목록·기능 플래그·모델 설정이 없으면 닫힌 상태 유지.
2. 클라이언트가 보낸 정답·루브릭·교재·모델을 신뢰하지 않고 서버의 검수된 카탈로그에서 ID로 조회. 생성한 카드 채점 시에도 해당 사용자의 서버 저장 결과만 사용.
3. 단원별 계약으로 생성 호출 → 별도 검증 호출에서 직접 문제를 풀고 자연스러움·문법·난이도·복수 답·중복·누출·맥락 변경·자체 완결성을 검토. 하나라도 실패/불확실하면 학습에 게시하지 않음.
4. 사용자·문제·답변·모델·원본 리비전 해시로 결과 재사용. 동일 생성 요청은 같은 결과를 재사용한다. 무한히 다른 변형을 뽑는 정책이 아니다.
5. SQL 예약·캐시는 RLS 활성, anon/authenticated 접근 금지, service_role만 사용. 트랜잭션 잠금으로 예약·일일 한도(사용자 10, 전체 50)를 원자적으로 처리한다. 실패도 한도에 포함하고 60초 뒤 최대 한 번 재시도, 멈춘 실행은 5분 뒤 한 번 회복할 수 있다. 키는 클라이언트에 넣지 않는다.
6. 출력 길이·완결 여부·형식 검사 및 60초 모델 타임아웃. 실패하면 기존 카드·진도·자기 평가 경로를 유지한다.

현재 온라인 생성의 대상은 **단일 어휘·문법 문자 카드**다. 새 독해 지문 묶음 생성, 새 청해 대화·TTS 생성은 온라인 생성 대상으로 허용하지 않는다. 준비된 지문·음성 표본만 실행한다. 이 제한을 사용자 화면과 요청 검증에 반영했다.

원격 활성화에 필요한 작업/설정:

| 항목 | 현재 상태/필요 값 |
|---|---|
| `202611030001_concept_lab_jobs.sql` | 새 마이그레이션 작성, 실제 DB 적용·권한·동시성 테스트 미수행 |
| `concept-lab` 함수 | Deno 타입 검사·로컬 실행/인증 없는 요청 차단 검증, 원격 배포 미수행 |
| `OPENAI_API_KEY` | 기존 서버 비밀과 공유 가능. 값 조회·출력하지 않았고 이번 기능으로 호출하지 않음 |
| `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` | 서버 환경. service_role은 앱에 넣지 않음 |
| `CONCEPT_LAB_MODEL` | 사용할 모델을 서버에서 명시해야 함. 계정 가용성·가격·생성/채점 품질 확인 후 선택 |
| `CONCEPT_LAB_ALLOWED_USERS` | 허용 사용자 UUID 목록. 기본 미설정이면 모두 차단 |
| `CONCEPT_LAB_ENABLED=1` | 서버 활성화. 현재 설정하지 않음 |
| `EXPO_PUBLIC_CONCEPT_AI_ENABLED=1` | 앱의 공개 기능 플래그일 뿐 키가 아님. 현재 설정하지 않음 |

카탈로그 동기화는 `node scripts/build-concept-catalog.cjs`. 키가 아닌 검수 콘텐츠만 서버 JSON으로 만든다. 서버 연결 뒤 **인증/RLS·한도·캐시·실제 모델 결과·비용**을 별도로 확인해야 한다. Docker 실행 파일은 있으나 로컬 daemon이 꺼져 있어 DB 마이그레이션 검증은 하지 않았다. 테스트 통과를 운영 DB 검증으로 해석하지 않는다.

## 비용·음성

이번 작업의 별도 **유료 API 호출 0회 / 신규 API 비용 $0**. 이전 N2의 $15 승인을 새 교재 예산으로 재사용하지 않았다. 이 대화에서 모델이 작성한 표본과 로컬 Windows OCR, 이미 저장된 음성을 사용했다.

새 음성 서비스 가입은 필요하지 않았다. 재사용 음성은 기존 N3 ID의 休日 단어와 AI 예문이다. 재사용은 복습 데이터를 합치는 것이 아니다. 교재 청해 MP3 확보·권한 확인과 새로운 대화 TTS 제작·파일 캐시는 남은 작업이다. 기기 실시간 받아쓰기는 설치·권한이 지원될 때만 노출하며 일본어/한국어를 선택한다. 유료 전사 fallback은 이 실험에서 자동 호출하지 않는다.

온라인 AI를 켜면 기존 OpenAI의 토큰 요금이 발생한다. 생성은 검증을 포함해 최대 2회, 채점은 1회/캐시 없는 요청이며 각각 출력 최대 3,500토큰이다. 요금은 `(입력 토큰 × 모델 입력 단가 + 출력 토큰 × 모델 출력 단가) / 1,000,000`으로 계산한다. 모델·요금·새 예산을 확정하기 전에는 활성화하지 않는다. [공식 가격표](https://developers.openai.com/api/docs/pricing)를 확인하며, 기존 앱의 옛 모델명이 이 실험의 확정 모델/가격이라는 뜻은 아니다. 호출 수 제한은 달러 예산 보장의 대체물이 아니다.
