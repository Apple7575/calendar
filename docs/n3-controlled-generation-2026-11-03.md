# N3 오답 기반 수동 생성과 개념별 변화

**후속 최신 상태:** [문법·독해 우선 확장과 합성 청해](n3-grammar-reading-listening-2026-11-03.md). 새 학습 가능 111문항, 합성 음성 3개를 추가했다. 자료 검수·음성 제작에 실제 유료 호출이 발생했으며 같은 누적 $5 한도에 포함했다. 아래의 0건·$0 및 원음 확보 전 보류는 이전 시점 기록이다.

2026-11-03. 브랜치 `feat/n3-concept-flashcards`. 기존 N3/N2 단어장과 분리한 개념서 표본 실험의 후속 구현이다. [기존 추출·카드 구현 기록](n3-concept-lab-2026-11-03.md)의 초기 서버 미연결·원격 변경 없음 기록은 **이 문서 작성 전 상태**다.

## 사용하는 순서

미리보기: **http://localhost:8082/?conceptDemo=1**. 웹 기록은 실험 전용 저장소에만 남는다. 일반 앱에서는 학습 → 내 단어장 → 개념서 N3 실험으로 들어간다.

1. 기존 플래시카드를 공부하고 ‘다시’ 등으로 자기 평가한다. 단순 예시 미리보기는 통계에 들어가지 않는다.
2. 실험 홈의 **오답으로 AI 새 문제 만들기**를 누른다. 추천 목록에서 개념, 연습 목표, 카드 유형, 추천 이유, 문항 수를 보고 직접 체크한다. 처음에는 아무것도 선택되지 않는다.
3. **선택한 N개 생성**을 눌러야 유료 생성이 시작된다. 추천 표시·체크·예산 조회는 모델을 호출하지 않는다. 생성과 별도 검증을 통과한 결과는 ‘검토 대기’에만 보관한다.
4. **문제·정답 검토 → 정답·해설 확인 → 이 문제를 학습에 추가**를 눌러야 실제 학습 카드가 된다. 추가하지 않고 보관할 수도 있다. 기존 카드·응답·복습 일정은 보존한다.

후속 요청으로 **전체 선택 / 전체 해제**를 추가했다. 비활성 항목은 제외하며 오늘 남은 한도까지 추천 순서로 선택한다. 한도 때문에 일부만 선택되면 안내 문구를 표시한다. 전체 선택만으로는 생성하지 않는다. 웹 테스트에서 2개 일괄 선택·해제와 남은 한도 1개일 때의 선택 제한을 확인했다.

### 전체 PDF 분량의 잠정 추정

전수 추출 전의 작업량 추정이며 확정 문항 수가 아니다. 목차 PDF 4–5, 기존 표본과 추가 50·70·100·124·150·200·230·248·286·308·330·350페이지의 밀도를 확인했다. 추가 페이지는 렌더링해 분량만 검토했으며 추출 검수 완료 상태로 올리지 않았다. 근거 이미지는 상위 `output/concept-lab/n3-20261102/estimate-survey.jpg`다.

| 범위 | 중복을 정리한 기본 카드·질문 예상 |
|---|---:|
| 어휘: 읽기·뜻·표기·문맥·용법 | 약 1,500–3,000 |
| 문법: 의미·접속·비교·적용 | 약 400–800 |
| 독해: 지문 묶음의 질문 | 약 40–80 |
| 청해: 음성 묶음의 질문 | 약 50–100, 원음 확보 전 보류 |

합계는 반올림해 **약 2,000–4,000문항**이다. 어휘표의 반복 어휘를 통합하고 모든 단어를 모든 유형으로 복제하지 않는 가정이다. 어휘표는 페이지당 수십 항목, 문법은 개념별 여러 평가 목표, 독해·청해는 지문당 소수 질문으로 산정해 범위를 넓게 잡았다. 교재에 이미 실린 연습문제만 세는 경우는 별도 관점으로 대략 400–700문항으로 추정하며 앞 합계에 더하는 수가 아니다. 전수 추출·중복 제거·허용 답안 검수 후 수치는 달라진다.

AI 오답 변형은 이 기본 분량에 포함하지 않으며 사용자가 선택할 때만 늘어난다. PDF는 374페이지이며 목차의 376쪽 이후 모의고사는 포함되지 않는다. $5는 AI 생성·검증의 누적 상한으로 유지한다. 이 추정은 전체 교재 AI 처리나 모든 문항의 유료 검수를 $5로 완료할 수 있다는 비용 보장이 아니다.

최근 30일의 유효한 오답과 수정된 평가를 사용한다. 반복 오답은 더 작은 단계, 개념 혼동은 비교, 활용 오답은 접속·활용 등으로 추천한다. 생성 대상은 어휘·문법 문자 카드다. 새 듣기 음성·독해/청해 문제 묶음의 AI 생성은 연결하지 않았다. 지원하지 않는 듣기 목표는 이유와 함께 비활성화한다.

하루 생성 한도는 기본 2개, 설정 최대 5개다. 실패 요청도 일일 횟수에 포함하며, 기존 준비 표본을 추가한 기록은 유료 생성 횟수로 세지 않는다. 개념별 생성 간격·이미 생성한 목표·직접 수정한 원본을 확인한다. 자동 생성·자동 재시도·자동 학습 추가는 없다. 실패 후 직접 다시 선택하면 새 요청으로 비용이 발생할 수 있다. ‘서버에 저장된 결과 확인’은 기존 완료 결과만 가져오며 새 모델 호출을 하지 않는다.

## 개념별 예전과 지금

**학습 현황·평가 수정 → 개념별 변화**에서 최근 7일과 그전 7일을 비교한다. 학습일 경계는 기존 앱과 같은 오전 4시다.

- 각 기간의 정답 비율과 응답 수, ‘다시’ 횟수, 학습 날짜·카드 수를 함께 표시한다.
- 기존 문제와 처음 보는 변형 문제의 첫 응답, 힌트 없이 맞힌 응답, 능력별 결과를 구분한다.
- 두 기간 모두 응답이 3개 이상일 때 15%p 이상 상승/하락이면 향상/하락, 나머지는 비슷으로 표시한다. 표본이 부족하면 판단 보류다.
- 자기 평가에 근거한 변화이며 객관식 시험 성적이나 숙련도 진단이 아니다. 답변 속도만으로 암기 여부를 판단하지 않는다. 평가를 수정하면 비교에도 반영한다.

새 변형 문제 한 번의 실패로 원래 카드의 일정이나 개념 전체를 초기화하지 않는다. 현재는 4개 개념의 대표 표본이다. 전체 PDF 처리나 모든 개념의 통계가 완료된 것은 아니다.

## 5달러 비용 제한

사용자 지정 **누적 총 $5**를 별도 서버 예산 `n3-concept-lab`에 적용했다. 일일 5달러가 아니며, N2 제작 예산과 별개다. 이 실험의 모든 계정이 하나의 누적 한도를 공유한다. 생성과 별도 검증 비용을 모두 합산한다.

고정 모델은 `gpt-5.4-mini-2026-03-17`이다. [공식 모델·가격 문서](https://developers.openai.com/api/docs/models/gpt-5.4-mini)의 입력 $0.75/백만 토큰, 출력 $4.50/백만 토큰을 적용했다. 최대 두 번 호출, 호출별 입력 40,000 UTF-8 바이트·출력 3,500토큰 제한이며, 요청 시작 전에 **$0.40을 보수적으로 예약**한다. DB 잠금 아래 예산을 확인하므로 동시 요청도 예약 한도를 넘겨 시작할 수 없다. 완료 후 보고된 토큰 수로 추정 정산한다. 네트워크 단절 등으로 비용을 모르면 예약액을 유지한다. 남은 예산이 예약액보다 적으면 추가 생성을 막는다.

이는 토큰 기반 추정·예약 통제이며 OpenAI 청구서 대조 완료액은 아니다. 모델이나 요금을 바꾸려면 예약 상한과 정산 요율을 함께 재검증해야 한다. 작업 종료 확인 시 서버 요청 **0건**, 추정·예약 사용액 **$0**, 예산 **$5**였다. 개발 테스트에서 실제 유료 모델 호출은 하지 않았다.

## 실제 연결 상태와 보안

Supabase 프로젝트 `qlurqptsnvxvlbsvpjie`에 전용 마이그레이션 두 개를 적용하고 `concept-lab` Edge Function을 배포했다. 상태 ACTIVE, 버전 1, JWT 검증 활성화. 함수 ID `f4480634-f323-4670-a696-764b2ad19b4b`, 배포 해시 `aa4cc5e346cd1fbd77ff1f7c0bcf045a033a8abfd00f0bf036dd4f6a2d013352`.

구글 계정 연결과 서버 `OPENAI_API_KEY`·해당 모델 접근 권한이 필요하다. 로그인한 실제 계정의 키 준비 상태와 유료 생성은 이번 검증에서 호출하지 않았다. 화면의 예산 상태 조회가 준비 여부를 표시한다. 준비되지 않으면 생성을 막으며 자기 평가 학습은 계속된다. 클라이언트에는 유료 API 키가 없다.

서버가 정식 원본·개념·평가 기준을 가져오고, 클라이언트가 보낸 답·루브릭·모델은 신뢰하지 않는다. 생성 후 별도 검증 단계에서 목표·자연스러움·명확성·난이도·답 노출·중복을 확인한다. 실패 결과는 학습 카드로 공개하지 않는다. 원본/개념 연결과 생성 결과를 서버에 저장해 같은 요청을 재조회할 수 있다.

전용 jobs/budget 테이블은 RLS 활성화, anon/authenticated 직접 접근·예약 RPC 실행 권한 없음, 서버 service role만 사용한다. 보안 점검의 ‘RLS enabled, no policy’ INFO 두 건은 이 비공개 테이블의 의도된 기본 차단 상태다. 관련 없는 기존 테이블·정책은 변경하지 않았다.

**새 앱 바이너리·EAS Update·TestFlight는 배포하지 않았다.** 이번 원격 반영은 이 기능의 전용 DB·서버 함수뿐이다. 실기기 동작과 실제 모델의 일본어 품질은 아직 검증하지 않았다.
