# 하루 타임라인 (2026-11-05)

기록 탭 맨 위 `오늘 하루` 카드와 `전체 보기` 화면(`DailyTimeline`). 하루 기준은 앱과 같은 04시다.

## 사용자 결정
- 외부 앱 사용량 보고서는 만들지 않는다. DeviceActivityReport를 쓰지 않는다.
- 노는 시간은 앱 구분 없이 **켠 시간** 기준이다. 실제 사용 분(consumed)과 다를 수 있고, 화면에 그렇게 적는다.
- 기록 전 날짜는 `기록 없음`이다. 0분으로 표시하지 않는다.

## 노는 시간 기록
- 시작과 끝은 `ScreenTimeStorage.update`의 쓰기마다 `recordPlay`가 정한다. 켜짐의 뜻은 `연결됨 && usingRewards && !locked`로, 앱 잠금이 실제로 풀린 상태와 같다.
- 잔액 소진은 확장의 사용량 콜백, 취침 잠금은 21시 콜백, 04시 전환은 다음 쓰기에서 닫는다. 앱이 꺼져 있어도 확장에서 닫힌다.
- 취침 잠금을 늦게 알아채도 끝 시각은 21시를 넘지 않는다.
- `recordPlay`는 잠금 상태를 읽기만 한다. 보상 원장과 기존 필드를 바꾸지 않는다.

## 실제 사용 분
전체 보기의 노는 시간 아래에 `실제 사용 N분`을 작게 적는다(사용자 확정). 오늘은 기기의 consumed, 지난날은 04시 전환 때 남긴 값이다. 값이 없는 날은 이 줄을 생략한다. 폰은 60일, 앱 데이터는 400일까지 남긴다. 건너뛴 날은 값이 없다. 복사본일 뿐이라 보상 원장과 빚 계산은 읽지 않는다.

## 알려진 오차
- 확장 콜백이 오지 않으면 다음 쓰기(앱을 열 때 등) 시각에 닫힌다. 21시 상한만 보장된다.
- 벌점과 보상 변경은 앱에서 동기화될 때 반영된다.

## 저장과 복구
- 폰 공유 파일: `playLog` 최대 200행, 약 8 KB. 넘치면 오래된 행을 버리고 `playLogSince`를 옮긴다.
- 앱 데이터: `data.playLog` 최대 3000행, 약 130 KB, 대략 1년. 백업에 함께 들어간다. 넘치면 그 날짜들은 `기록 없음`으로 돌아간다.
- `coverage`는 폰이 기록하던 구간이다. 연결을 끊은 날과 재설치 사이의 날은 `기록 없음`이다.
- 복구 검사에 이 필드를 넣지 않았다. 옛 빌드의 복구 검사는 모르는 필드를 거르지 않고, 새 빌드는 깨진 행을 없는 셈 친다.
- Swift 필드는 모두 선택 값이라 옛 파일을 그대로 읽는다.

## 단어장 묶음
같은 덱의 응답 간격이 10분 이하면 한 줄로 묶는다. 장수는 서로 다른 카드 수, 시간은 응답 시간의 합(카드당 120초 상한)이다. 취소한 응답은 뺀다. 응답 기록이 없는 옛 날은 줄을 만들지 않고 시각 기록이 없다고 적는다.
